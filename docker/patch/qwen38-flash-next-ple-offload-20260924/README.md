For an image stage or source overlay, first check out this Relax branch at a fixed commit and the three official dependency commits shown above. Run `apply.sh` on the clean dependency checkouts. Put `Megatron-Bridge/src`, `Megatron-LM`, `transformers/src`, then Relax on `PYTHONPATH`, in that order. Verify that `megatron.core.transformer.per_layer_embedding`, `megatron.bridge.models.qwen.qwen4_exp_bridge`, `transformers.models.qwen4_exp.modeling_qwen4_exp`, and `relax` import from those exact checkouts. Keep the known working Python/CUDA dependency pins. The default `docker/Dockerfile` and `docker/patch/latest/megatron.patch` use a different baseline and must not be mixed with this bundle.

An existing container can use a versioned source overlay without rebuilding the image if its native PyTorch, CUDA, Transformer Engine, and Triton dependencies are compatible. Put the four fixed checkouts at the same absolute path on every worker, preferably in a shared `/mnt` version directory. Keep that directory unchanged for the lifetime of the training job; create a new directory and job for source changes. Set the Ray job's `runtime_env.env_vars.PYTHONPATH` to the same ordered paths and its working directory to the fixed Relax checkout. An interactive shell export does not propagate to Ray workers. Record the Relax commit, patch SHA256, applied dependency trees, runtime imports, and config SHA256 before training. Do not overwrite an earlier experiment's source overlay or checkpoint.

For a copied runtime overlay without `.git`, compare SHA256 of `per_layer_embedding.py` = `9fa1dad78673f61be39a645c44fd74fa7f96cbe5730507be133f0f4898166b3f`, `ple_host_lookup.py` = `e00bcacf075f561a773a87bc5d96f3bec60070bb004ffeb2895f6af8b8819663`, and `qwen4_exp_bridge.py` = `f09c360bf00f5b0f282ecd37a2f985c64777293bc3dc421aefc2bfc0e4716a89`. Confirm the actual Python `__file__` paths before a Ray submission.

The candidate sets `QWEN48_PLE_CPU_OFFLOAD=1` in the **Ray runtime environment**. Only the TP row shard of the frozen N-gram table is pinned on CPU; the table is a persistent buffer, so it is excluded from optimizer parameters and included in DCP. The lookup preserves existing TP reduce-scatter/SP output and the packed CP, hash, halo, and stream code paths. BF16 CUDA uses the pinned-row Triton lookup adapted from ModelScope mcore-bridge `7baa28c302ecae36d06a7e25ff65cf7169eda7b6`; other supported dtypes use bounded CPU gather. Bridge import applies HF FP8 scalar `weight_scale` once when the shard dtype is FP8. Host-table HF export streams bounded GPU PP/TP collectives and writes BF16 shards; it does not re-quantize to FP8.

Use the [`ple-offload-gate` launcher](../../../scripts/training/sft/run-qwen38-flash-next-48l-vl-full-sft-128xgpu-t8p8c2e16-ple-offload-gate.sh) with `QWEN48_PLE_CPU_OFFLOAD=1` and `QWEN48_PLE_STREAMED=1` in the Ray runtime environment, plus a unique `qwen38-48l-ple-offload-*` checkpoint name. It leaves PLE projection, norm, and conv trainable and freezes vision/aligner and QSA indexer. It requires `MODEL_DIR`, `PROMPT_DATA`, `QWEN48_PRECISION_CONFIG`, `RAY_ADDRESS`, `SAVE_DIR`, and `EXP_NAME`. For execution it additionally requires a reviewed `RUNTIME_ENV_JSON` **string**, `SUBMISSION_ID`, `QWEN48_TRAIN_AUDIT_DIR`, `QWEN48_GPU_CLEAR_VERIFIED=1`, and `QWEN48_EXECUTE=1`; the latter defaults to a local preflight that does not validate the Ray runtime environment. Do not resume an older all-PLE-frozen optimizer into this trainable configuration. Start from the pinned HF source and resume only this configuration's own checkpoint.

Optional Relax-side accelerators use the same dependency patch trees and are **off by default**. `QWEN48_PLE_FUSED=1` activates the per-stream PLE gate/norm/conv Triton chain, adapted from ModelScope `7baa28c`, while preserving packed-CP reconstruction and checkpointing. `QWEN48_QSA_SELECTED_TRITON=1` with `MCORE_QSA_SPARSE_BACKEND=id_sparse` activates the adapted selected-block Tensor Core QSA kernel; head widths below 128 retain the existing ID kernel. A full 128K document still needs a roughly 512 MiB packed bitset per QSA call. Compare QSA selected-index against the same `id_sparse` backend with selected-index disabled, and run PLE fusion as a separate A/B job. Neither accelerator has passed a 128K whole-step gate.

## Verification boundary

This bundle reconstructs from official bases with exact tree checks. Local gates passed TP2 CPU/BF16 lookup with SP on/off, packed CP2 PLE forward and parameter gradients, TP1/TP2 MCore DCP save/load of pinned host rows, synthetic FP8 scalar-scale import, and TP2/PP2 BF16 HF export. These tests do not establish real-image 128K optimizer membership, multi-node DCP recovery, steady throughput, or 15% MFU. Before a target run, verify ownership of the existing jobs and physical GPUs; collect all-rank memory, loss, optimizer, checkpoint-read, and ordinary-step performance evidence. The earlier run with the entire PLE frozen is a different checkpoint configuration.
